# SCRUM-76 - System Email Handoff

## Provider

The CRM system mailbox is hosted on Stalwart at `mail.ongdngolu.org`.

Backend automatic emails use SMTP with:

- `SMTP_HOST=mail.ongdngolu.org`
- `SMTP_PORT=587`
- `SMTP_USER=noreply@ongdngolu.org`
- `SMTP_FROM=noreply@ongdngolu.org`
- `SMTP_PASS` from the Stalwart mailbox password

Do not commit real SMTP passwords.

## Backend Integration

Automatic sends are centralized in `src/system-email/system-email.service.ts`.

Current connected workflows:

- password reset emails
- real estate contract signature links
- real estate contract signed confirmations
- rent payment reminders
- authenticated test send: `POST /system-email/test`

Every send writes a row in `system_email_logs` with status `pending`, `sent`, `failed`, or `skipped`.

## DNS Required

For `ongdngolu.org`, keep these records in Lightsail DNS:

- MX: route mail for `ongdngolu.org` to `mail.ongdngolu.org`
- A: `mail.ongdngolu.org` points to the Lightsail public IP
- SPF TXT on root: authorize the mail server, for example `v=spf1 mx a:mail.ongdngolu.org ~all`
- DKIM TXT: copy the selector/value generated by Stalwart for `ongdngolu.org`
- DMARC TXT on `_dmarc`: start with `v=DMARC1; p=none; rua=mailto:noreply@ongdngolu.org`

After stable delivery, DMARC can be tightened from `p=none` to `quarantine` or `reject`.

## Operational Notes

- If SMTP is not configured, non-required automatic emails are logged as `skipped` and user actions continue.
- Required sends, such as `POST /system-email/test`, return an error when SMTP is missing or delivery fails.
- Error logs redact the SMTP password before writing backend logs or DB rows.
